# Changelog

All notable changes to the contracts repository. `VERSION` and
`contracts.json.release_version` carry the release; see `docs/versioning.md`.

## 1.4.0

Minor release. Four new wire contracts, a pre-tag release preflight, and CI
fixes. Reconstructed from `git log v1.3.0..main`.

### Compatibility

Nothing in the existing wire surface changed. `git diff v1.3.0..main` shows no
edit to any schema that existed at 1.3.0, and `contracts.json` gained entries
without altering or removing any. The only change to a pre-existing contract
document is an added paragraph in `docs/opening-book-v1.md` clarifying (not
changing) the orientation of stored actions.

New wire contracts (all additive; no existing reader or writer is affected):

- `engine-request.v1`
- `engine-response.v1`
- `engine-response.v2` (major 2 within its own family; `engine-response.v1` is
  frozen and keeps validating)
- `opening-probe.v1`

Changed: none. Breaking: none for existing registered contracts.

Things a consumer can still trip on:

- The registered request/response name is the bare `engine-request.v1` /
  `engine-response.v1`. Before registration all implementations spoke
  `quantik.engine-request.v1`. The documented migration (QW-019 D3): servers
  accept both spellings for one minor cycle, and the prefixed spelling is
  rejected starting at the next minor (1.5.0). This is a deprecation of an
  unregistered spelling, not a break of a registered contract.
- `contract_version` in fixtures and `minimum_expected_contract_release` in
  `contracts.json` move to `1.4.0`; validators require fixture
  `contract_version` to equal the release, so downstream stacks pinning
  contracts must adopt the new fixtures together with the new tag.

### Added

- `engine-request.v1` and `engine-response.v1` registered (#24): schemas,
  docs, and fixtures captured from the real implementations. Documents the
  `quantik.` prefix rename migration.
- `engine-response.v2` (#27 design, #29 registration): ranked `candidates`
  (each with `action_index`, `score`, and a `unit` of visits, logit, prior or
  value), a principal variation `pv` (`pv[0] == action_index`), optional
  `engine_config`, and a required `certainty` of `estimate` or `proof`. Schema,
  synthetic fixtures, a rejection-case file, and validator checks for `pv[0]`
  and candidate uniqueness.
- `opening-probe.v1` (#28 design, #30 registration): a read-only,
  symmetry-aware lookup artifact derived from `opening-book.v1`. Schema,
  `contracts.json` entry, synthetic and invalid fixtures, and a reference
  probe in `scripts/validate_contracts.py`.
- `scripts/release_preflight.py` (#26): fails before the tag is cut, not
  after. Checks the tag is absent, `VERSION` matches the tag at the ref, and
  referenced action paths exist. `release-contracts.yml` gains a
  `preflight_only` dispatch input and re-runs the preflight, tolerating the
  now-existing tag, in the release job.
- `docs/opening-book-v1.md`: stored action indices are in the canonical
  representative's orientation; optional edge `transform_id` documented.
- `docs/consistency-checks.md` (#31): demonstration that a one-sided release
  bump no longer deadlocks the opening-book consistency check, with a control
  run against the `v1.2.0` validator. The summaries in it are hand-built to
  the real depth-4 shape, not generated by the engines.

### Changed

- `validate-contracts` no longer hardcodes the release (#25): the
  `--expected-release` argument was dropped from the workflow, so a version
  bump no longer needs a workflow edit.
- GitHub Actions moved off Node 20: `actions/checkout` v4 to v7,
  `actions/setup-python` v5 to v7, `actions/upload-artifact` v4 to v7, across
  all workflows (`ac208de`).

### Release bookkeeping

- `VERSION`, `contracts.json` (`release_version` and both
  `minimum_expected_contract_release`), fixture `contract_version` /
  `contracts_release` fields, test expectations, `README.md` and
  `docs/README.md` moved from 1.3.0 to 1.4.0.
